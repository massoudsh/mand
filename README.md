# ماند (Mand)

**ماند — جایی خرج کن که واقعاً اثر می‌کند.**
*Mand — Spend your growth budget where it actually works.*

موتور هوشمند تصمیم‌گیری نگهداشت (Retention)، Uplift و بهینه‌سازی مشوق برای پلتفرم‌های مصرفی ایرانی.

## مسئله

پلتفرم‌های مصرفی ایرانی بودجه‌ی زیادی روی پیام و تخفیف خرج می‌کنند، اما نمی‌دانند کدام مداخله
incremental value می‌سازد و کدام فقط margin می‌سوزاند. `churn prediction` می‌گوید چه کسی در
خطر است؛ سؤال درست‌تر این است که **روی چه کسی مداخله واقعاً اثر دارد**.

## راه‌حل

ماند به‌جای فقط پیش‌بینی churn، برای هر کاربر uplift هر مداخله (پیام، push، تخفیف، cashback) را
تخمین می‌زند، هزینه‌ی incentive را در نظر می‌گیرد و تصمیم می‌دهد:

- روی چه کسی مداخله کن
- از چه کانالی
- چه زمانی
- با چه نوع و مقدار مشوقی
- و کجا **اصلاً بودجه‌ای خرج نکن**
- **چرا** — هر تصمیم با دلیل قابل‌فهم همراه است (Explainability Engine)، نه فقط یک عدد

## بازار هدف

GrowthTech سازمانی — مارکت‌پلیس‌ها، فین‌تک‌ها و اپ‌های مصرفی ایرانی که بودجه‌ی واقعی روی
retention و incentive خرج می‌کنند و ROI برایشان حیاتی است.

## نقشه راه

جزئیات کامل فازها در [ROADMAP.md](./ROADMAP.md) و issueها/milestoneهای گیت‌هاب.

## وضعیت

پروژه در فاز ۰ (اکتشاف و انتخاب design partner) است. یک MVP دمو با دادهٔ مصنوعیِ واقع‌نما، API و داشبورد تصمیم RTL برای اعتبارسنجی قرارداد داده و تجربهٔ محصول در اختیار است.

## اجرای MVP

نیازمندی: Node.js 20 یا جدیدتر.

```bash
npm test
npm start
```

ساختار اجرا:

- `frontend/` — داشبورد RTL و رابط کاربری
- `backend/` — API و محاسبات تصمیم
- `db/` — نمونه‌دادهٔ مصنوعیِ بدون اطلاعات شخصی واقعی

APIهای موجود:

- `GET /api/health` — وضعیت سرویس
- `GET /api/overview` — شاخص‌ها و تصمیم‌های پیشنهادی
- `GET /api/segments` — سگمنت‌بندی رفتار کاربران
- `GET /api/campaigns` — کمپین‌های چندکاناله
- `POST /api/campaigns/:id/activate` — تأیید اجرای یک کمپین پیش‌نویس
- `GET /api/report` — گزارش مدیریتی شش‌ماهه
- `GET /api/comparison` — برگهٔ مقایسهٔ رقابتی و شکاف‌ها

داشبورد پنج بخش دارد: تصمیم‌ها، سگمنت‌بندی، کمپین، گزارش و مقایسهٔ رقابتی.

## پنج قابلیت اولویت‌دار بعدی

- هاب اتصال کانال‌ها برای SMS، push، تلفن و CRM — P0
- سازندهٔ سفر مشتری با trigger و شاخه‌بندی — P0
- کیف پول وفاداری با امتیاز، انقضا و سقف هزینه — P1
- مرکز آزمایش A/B و Holdout با سنجش uplift — P1
- تایم‌لاین تماس و خدمات مشتری — P2

این اولویت‌ها در تب «مقایسهٔ رقابتی» با دلیل و ارزش محصول نمایش داده می‌شوند؛ دادهٔ رقبا برآورد تحلیلی است و قبل از تصمیم تجاری باید با مصاحبه و بررسی رسمی اعتبارسنجی شود.
